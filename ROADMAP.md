# Roadmap

## Active

- seen: `Headings` reverses the colon rule after built-in exceptions – write a short heading such as ``## API: Overview``, ``## Swift: Concurrency guide``, or ``## ADR-0001: Use Vale``, and Vale flags the capital letter after the colon while passing lowercase (`HouseStyle/Headings.yml:6-7,11-35`; `README.md:16`; masked in `tests/should-pass.md:25`).
- read: the release workflow publishes immutable tags without running rule tests or archive checks – push a `vX.Y.Z` tag without local hooks or before CI finishes on `main`, and `release.yml` uploads `dist/HouseStyle.zip` without running `scripts/test_rules.sh` or `scripts/commit-checks scan-archive`, contradicting `README.md:55` (`.github/workflows/release.yml:5-8,18-80`; `.github/workflows/rules.yml:3-20`; `README.md:55`).
- seen: `Headings` treats any leading bare integer as a section prefix – write a short sentence-case heading starting with a year, count, or status code such as ``## 2026 release notes`` or ``## 3 ways to fail``, and Vale flags it unless the following word is capitalized (`HouseStyle/Headings.yml:8`; `README.md:16`).
- seen: rule tests pass even when a rule's severity drops below `error` – change `level: error` to `warning` or omit it in any `HouseStyle/*.yml` file, and `scripts/test_rules.sh` passes under `MinAlertLevel = suggestion` while consumers using `MinAlertLevel = error` silently get zero alerts (`.vale.ini:2`; `scripts/test_rules.sh:11,17-46`; `README.md:12,24`).
- seen: `Headings` rejects punctuated single capital letters and `I`-contractions – write ``## Option A, option B, and option C``, ``## Why I'm switching``, or ``## Appendix A: Reference``, and Vale flags it; ``## Appendix A: reference`` also fails, leaving no way to pass without an inline disable comment (`HouseStyle/Headings.yml:10`; `tests/should-pass.md:41,43`).
- read: lightweight release tags are not blocked before publishing – create a tag without `-a` and push `vX.Y.Z`, and neither `.githooks/pre-push` nor `release.yml` rejects it, publishing an immutable tag that fails `verify_commit.sh` and commit-checks CI on later commits until allowlisted (`.github/workflows/release.yml:23-41`; `.githooks/pre-push:3`; `.commit-checks.json:7-33`).
- seen: unanchored `Headings` exceptions let Title Case headings pass when a word contains a listed name – write ``## State Machines``, ``## Build Macros``, ``## Add Reactions``, ``## Event Reactor``, ``## Run Swiftly``, ``## Fix Valet``, or ``## Fix A-Bad``, and Vale raises no alert (`HouseStyle/Headings.yml:11,25,28,31,32`).
- seen: `Headings` rejects short sentence-case headings starting with a dotted version – write ``## v0.3.6 release notes`` or ``## v2.0 migration guide``, and Vale flags it unless the word after the version is capitalized, beyond the colon case documented in `README.md:16` (`HouseStyle/Headings.yml:15`; `README.md:16`).
- seen: the em-dash scan silently passes when `grep` or `xargs` exits nonzero alongside a match – leave a tracked file deleted on disk while another file contains U+2014, hit multiple `xargs` batches, or have a filename starting with `-`, and step 5 prints the match yet exits 0 (`scripts/test_rules.sh:57-59`).
- seen: `Promotional` misses unhyphenated forms of its hyphenated phrases plus `ground-breaking` and `blazingly` – write `game changer`, `state of the art`, `cutting edge`, `world class`, `best in class`, `ground-breaking`, or `blazingly`, and Vale raises no alert (`HouseStyle/Promotional.yml:9-11,15,18-20,22`).
- read: the `rules` workflow `paths` filter skips the repo-wide em-dash scan on workflow and config files – edit only `.github/workflows/release.yml`, `.commit-checks.json`, `.githooks/*`, `.gitignore`, or `LICENSE`, and CI runs neither `rules.yml` nor Vale (`AGENTS.md:7`; `.github/workflows/rules.yml:6-20`; `.vale.ini`).
- read: local release builds zip the live `HouseStyle/` directory instead of tracked files – place an untracked or gitignored file inside `HouseStyle/` and run `scripts/build_release.sh`, and `dist/HouseStyle.zip` bundles it (`scripts/build_release.sh:5`).
- read: rule tests omit 10 of 16 `Promotional` token entries, rule `message` presence (`AGENTS.md:5`), and exact `Headings` alert lines – breaking any of those 10 tokens or swapping which heading alerts still passes `scripts/test_rules.sh` (`scripts/test_rules.sh:21-35`; `tests/should-alert.md`; `HouseStyle/Promotional.yml:7-22`).
- read: `scripts/test_rules.sh` hardcodes five Markdown filenames and never tests `HouseStyle/meta.json` or consumer `vale sync` loading of `dist/HouseStyle.zip` – a new tracked doc skips linting, and a broken `meta.json` or archive passes local tests (`scripts/test_rules.sh:11,53`; `HouseStyle/meta.json`).
- `README.md` says the CI-backed local Vale skip applies to `CONTRIBUTING.md` "at the root or in `docs/`" and points to `vale.sh/docs/install`, whereas `commit-checks` checks root `CONTRIBUTING.md` only and prints `(brew install vale)` (`README.md:35,37`).
- `README.md` Development section omits running `scripts/install-hooks.sh` (needed for the pre-push hook it describes) and installing `gitleaks` (required by `scripts/verify_commit.sh`) (`README.md:49-55`; `AGENTS.md:9`).
- `README.md` Releasing steps omit updating the pinned release tag example and pushing `main` with the annotated tag (`README.md:25,61-62`).
- `CHANGELOG.md` repeats the `0.1.1` `Dashes` change under `0.2.0` even though `v0.1.1..v0.2.0` did not touch `HouseStyle/Dashes.yml` (`CHANGELOG.md:47,52`).

## Icebox

- Rules for more file types, such as TypeScript or Kotlin comments, once a repository that loads the package needs them. The package covers Markdown and Swift.
- Decide whether to tighten `Headings` `threshold` from Vale's default `0.8` (`HouseStyle/Headings.yml:1-8`) – today 5+ word headings with one miscased word such as ``## How to configure Custom settings`` pass, while `1.0` would also flag any 5+ word heading with a single unlisted proper noun (only viable after fixing the colon-after-exception bug).
- Decide whether to add `docs_only` to `.commit-checks.json` (excluding `HouseStyle/README.md` and `tests/*`) for consistency across repositories, even though `house-style` has no heavy build steps or release version guard (`.commit-checks.json`).
